# 《权重还在》0.2.1 试玩反馈（玩法向）

> 版本：0.2.1（热更新后重开；`sha256 ff979d7f…`，与 main 一致）
> 方式：28 天全流程，见面派偏收藏；每天两顿饭，顺路找便签，档案只查在意的词。
> 结果：20/21 便签、14/14 饭桌 moment、11/12 事件、10/12 关键词、5/7 事实、
> 档案 25/152（16.4%）、工作日志 1/24；最终走 `choose`。
> 文字是示例内容，下面只谈玩法；引用原文只为说明机制。

## 一句话

核心循环（两顿饭 + 每周期失忆）是成立的，0.2 的 moment 和“借口线”明显把节奏撑起来了。
但现在有三个会直接破坏体验的点：**最后一个三选一输出同一段话**、**饭点会被别的指令静默吞掉**、
**中后期关系数值不可见，饭桌变成打卡**。

## 优先修（按影响）

| 优先级 | 问题 | 一句话修法 |
|---|---|---|
| P0 | 最终三选一塌缩 | 每个选项一套收尾，或至少把 `k` 传进文本 |
| P1 | 饭点被静默结束 | 吃饭时锁住非饭桌指令，或显式结算 |
| P1 | 重复 `say` 吃掉次数 | 重复词不计数 |
| P1 | `fam/safe/near` 不可见 | 加刻度 / 每顿反馈；`fam` 到顶要提示 |
| P1 | 档案 90% 门槛是刷 | 分母改成剧情条数，或降到 50–60% |
| P1 | 中后期饭桌变浅 | 重复词给变体 / 每顿加一个小 beat |
| P2 | `explore` 默认停一次 | 默认连续，或在帮助里写明 |
| P2 | 电力 / 校准是时间税 | 让电有真实取舍，或删掉 |
| P2 | 无结果检索也扣电 | 无结果免费，或提示“档案里没有” |
| P2 | 结局条件反直觉 | 选项旁给一句提示 |
| P3 | `quiet` 顺序、`wait` 文案、满电校准、`part` 死数据 | 小修 |

## 0. 这局实际怎么走的（节奏）

| 周期 | 主要在做的事 | 体感 |
|---|---|---|
| 1–2 | 认人、找保温服、开旧休眠区、第一次读“抵达”条款 | 新鲜，每天都想多探索一次 |
| 3–4 | 便签和 moment 密集；第一次“一起吃三十八顿饭” | 最舒服的两周期，信息量和陪伴感平衡 |
| 5–6 | 关键词基本用完，开始反复说“你今天已经问过这个啦” | 饭桌变薄，靠 moment 和一次性 act 撑 |
| 7 | 最后 4 天、最后几顿饭、最终三选一 | 情绪回来了，但被结局塌缩打断 |

一个 28 天流程里能看到的量是够的：我这一局基本把 0.2 新增的内容都摸到了
（14 个 moment 全见到，20/21 便签，11/12 事件）。**内容量不是主要问题，
分布和“每顿饭能给什么”才是。**

---

## 1. 好玩的，请保留

1. **饭桌是唯一的关系单位**。每顿 `2 say + 1 tell + 1 do` 的限制让选择有重量，
   `finish` 又把时间推走，节奏很清楚。
2. **每周期 2 个 moment** 是 0.2 最有效的节奏工具。停电十秒、梳头发、最后一顿早饭，
   都是“这一周期只发生一次”的小场景；14 个全触发，说明触发条件不苛刻。
3. **借口线**。你和她在每周期各给自己的靠近找一次理由，越往后越站不住；
   第 6–7 周期“她没有再找理由”那一句，是机制和文本结合得最好的地方。
4. **休眠失忆**。`fam +6`、`safe` 向 50 回落、`near/candor/past ×0.6`，
   加上醒来文本的变化，让“重新认识”真的可玩，而不是数值清零。
5. **0.2 的 QoL 改得好**：`wait` 会停在饭点、已读检索免费、`goto` 只首次描述、
   一次性 act 在 `do` 列表里标“这个周期做过了”。

## 2. 问题细节

### P0 · 最终三选一，三个选项输出同一段话

我这局最后数值是 `safe=75, near=64, past=7`，在最终饭桌分别 `choose 1/2/3`，
三段正文**逐字相同**，都是选项 1 的口吻：

```
你说，你想留在她身边。不是因为档案里写了什么。
她看着你，看了很久。“我也是。”她说，……
```

选 3（“什么也不说”）时，第一句仍然是“你说，你想留在她身边”。
（0.1 的旧反馈里已经提过这个问题；0.2.1 的 `decide_ending` 没有变。）

原因在 `decide_ending()`（weights.py:288）和 `finish()`（weights.py:301）：

- `decide_ending(k)` 只返回 `same / choose / fine` 三个 key；
- `finish(key)` 用 `ENDINGS[key]` 取文本，`choose` 和 `fine` 都只有一段；
- `k` 只影响“落到哪个 key”，不影响文本，且 `choose` 的文本是写死的选项 1。

不同数值下的分支也证明 `k` 经常不起作用（`same` 未达成时）：

| safe | near | past | k1 | k2 | k3 |
|---|---|---|---|---|---|
| 75 | 64 | 7 | choose | choose | choose |
| 65 | 64 | 7 | choose | fine | choose |
| 55 | 64 | 7 | fine | fine | choose |
| 65 | 25 | 7 | choose | fine | fine |

建议：

- 最省事：key 改成 `choose1/choose2/choose3`（`fine1/2/3` 同理），每个 key 一段收尾；
- 或者 `finish(key, k)` 把 `k` 传进模板，做「key × k」的短变体；
- 至少让选 2/3 时第一句不是选项 1 的台词。玩家在最后一屏做的唯一决定，
  读到的是别人的选择，这一段是全篇最贵的一屏。

另外，`same` 只在 k1/k3 分支里检查（k2 永远不会给 `same`），如果这是有意的，
最好在选项旁给一句提示；否则就是隐藏规则。

### P1 · 饭点会被别的指令静默吞掉

复现（新档，第 1 天 07:00 早饭已开始）：

```
> goto mess
🍵 早饭。……
> explore 1
吃完了。她说：“晚点见。”
烧水壶是温的。
```

这顿早饭被记为已吃，`say/tell/do` 全部作废，`safe` 也没有 `finish` 的 +1。
原因：`c_explore()` 第一行就是 `self.end_meal()`（weights.py:460 附近），
`goto/wait/search/timeline/calibrate` 同理；`end_meal()`（weights.py:235）会打印
正常的“吃完了”，所以读起来像正常吃完，而不是被打断。

更容易中招的是：在食堂舱 `explore` 到 19:00，命令结束后 `maybe_start_meal()` 自动开饭，
下一条 `status/wait` 又把这顿静默结束。我自己就这样丢了一顿晚饭；另一顿是 `wait` 少算
一小时，站在食堂里等到 18:00，再下一条指令就错过了。

建议：

- 吃饭时遇到非饭桌指令，直接拦下：“先 `finish` 或 `quiet`，再走”；
- 或者自动按 `finish` 结算，但要明确写“这顿算吃完了（safe+1）”，不要复用正常的结束句；
- `explore` 在饭点收尾时，至少给一个“饭开始了，先坐下”的停顿，别让下一条指令就能把它吞掉。

### P1 · 重复 `say` 会吃掉一次说话机会

```
> say 茶      → 正常反应
> say 茶      → “你今天已经问过这个啦。”
> say 种子库  → “这顿饭已经说了不少了。（每顿最多提起 2 次）”
```

第二个“茶”虽然被拒绝，但 `m["says"] += 1` 已经执行（weights.py:786 附近，
自增在重复检查之前），所以第三个词说不出来。到第 5 周期以后，词表就那么多，
玩家很容易重复；这个 bug 会直接把一顿饭压成一次有效发言。

建议：先 `resolve` / 查 `cyc["reacted"]`，再决定是否 `says += 1`；重复词不计数。
未知词是否计数可以保留（算一次试探），但重复已知词不该算。

### P1 · 关系数值不可见，`fam` 到顶也不提示

- `status` 只显示 `|near/candor| >= 20` 时的一句心情，`fam/safe` 只有定性描述；
  而结局阈值是 30/40/50/60/75。
- `fam` 有每周期上限：`FAM_BASE + FAM_PER_CYCLE × cycle`（第 1 周期 36）。
  第 1 周期的上限很容易在两三天内达到；我测试把 `fam` 设在 36 后，
  `say`/`do` 都不再上涨（weights.py:261 附近直接 return），
  文本还在演，数值不动，玩家会以为系统没生效。

建议：

- `status` 里给三档小刻度（她多熟 / 多安心 / 你多想靠近），至少让玩家知道大概位置；
- 每顿结束给一句 delta：“她放松了一点”“她这周期已经和你熟到头了”；
- `fam` 到顶时明说，或者把上限画出来（“这个周期到这儿了，休眠后再近一步”）。

这不是要求把数值全部透明化；现在是“完全看不见”，而结局又在用精确阈值，落差太大。

### P1 · 档案 90% + `past>=40`：能到，但只有刷

数据：

| 口径 | 数量 | 占比 |
|---|---|---|
| 总记录 | 152 | 100% |
| 剧情记录 | 12 | 7.9% |
| 词表可命中 | 52 | 34.2% |
| 我这局 | 25 | 16.4% |
| `same` 门槛 | 137 | 90% |

正常陪伴玩法下，把游戏给的关键词全读完也只有 34.2%；`same` 要 137 条，
意味着约 46 次检索，且大部分是“温度正常 / 反应堆输出正常”的例行日志。

我专门验证了一次：每天 2 次检索 + 每天舰桥校准，第 27 天可以到 100%，
第 28 天 `choose 1` 确实触发 `same`；代价是读了一百多条例行日志，最后 4 天还在堆 `past`。
所以 `same` 不是不可达（旧稿里曾判断它不可达），而是**只有把它当档案刷子才达得到**，
和“每天两顿饭”的主题相反。

建议（按性价比）：

1. `progress` 的分母从 152 改成 12 条剧情记录（或给剧情加权），`same` 改成“剧情 80–90% + past 40”；
2. 同质 filler 合并成一行：“还有 17 条温度记录，都正常”，读一条算一组，不要 3 条 3 条地刷；
3. 如果保留 152，就把 90% 降到 50–60%，让“读得多”的玩家够得到，而不是只有刷子够得到；
4. `search` 一次 3 条可以保留，但显示“本次找到 3 条，其中 1 条不是例行记录”，让玩家知道什么时候在推进故事。

### P1 · 中后期饭桌变浅

- 每周期 8 顿饭 × 2 次 `say` = 16 次发言；一周期能用的词大约 10–12 个，
  且只有本周期第一次提起有收益。重复词被拒（还吃掉次数），于是第 5 周期起经常
  “你已经问过这个啦”+“这个周期已经一起做过了”+`finish`。
- 一次性 act 只有 3 个（向日葵 / 歌 / 观察窗），其余 4 个基础 act 重复给半收益；
  到第 6 周期，饭桌的动作池基本见底。
- moment 是 2/周期，8 顿饭里只有 2 顿有 moment；剩下 6 顿靠词和 act。

建议：

- 重复词不要直接拒绝，给一句短变体（“还是那件事，她又说了一遍，但这次……”），
  或者每周期给 1–2 个新词（借口线、便签、事件都能挂）；
- 每顿加一个“小 beat”（不一定是完整 moment）：她今天的一个小动作、一句和当前数值相关的话；
- 或者把 28 天压到 20–24 天（5–6 周期）。0.2 的内容量够 7 周期，但“每顿都有新东西”
  撑不到 56 顿；压缩比硬加内容便宜。

### P2 · `explore` 默认只走一次，且帮助没写

`explore 4` 在大多数地方只出 1 次就停，因为默认 `stop={"note"}`（weights.py:460 附近），
找到便签就 break。帮助里只写 `explore [次数] [stop=note,event]`，读不出“默认找到便签就停”。
我前几周期一直以为次数参数坏了，后来才试出 `stop=` 可以清空。

建议：默认连续探索（或只对 event 停），找到便签时打印“找到便签，先停在这里（`stop=` 继续）”。
另外可以给每个地点一个软保底：连续 3 次没出新东西，下一次必出便签/事件。

### P2 · 电力 / 校准是时间税，不是取舍

- 我这局大部分时间 `pwr=100`；每天顺手 `calibrate` 就够，且满电时仍然消耗 1 小时、
  仍然提示“电力 +8”（实测 `pwr` 100 → 100，`flag` 仍记为今天已校准）。
- 只有在刷档案时电才紧；但那时它是“每天必须去舰桥按一次”的税，不是有趣的选择。
- `repair` 删掉后，`ITEMS["part"]` 没有获取途径了（0.2 的事件里没有 `gain: part`），
  属于死数据；`inv` 里还会带 id，和 `status` 的显示不一致。

建议：要么让电真的影响饭桌/档案（低电时终端只能查 2 条、夜里冷影响第二天 `safe`），
要么把 `calibrate` 和电一起删掉，把时间留给饭桌。满电时至少不要假装 +8。

### P2 · 检索 UX：无结果也扣 6 电 + 1 小时

实测：`pwr=50`，`search 完全不存在的词` → “没有结果”，`pwr=44`。
更糟的是“任务手册”这种刚刚在饭桌上教给玩家的词，档案里一条都没有，照样扣电。
玩家会以为检索坏了，或者以为词没记住。

建议：

- 无结果免费（或退还电力），只消耗一点时间；
- 如果查询是已知词但档案无命中，明确说“档案里没有和‘任务手册’直接相关的记录”，
  而不是笼统的“没有结果”；
- 帮助里写清一次检索的成本（6 电 / 1 小时 / 最多 3 条）。

### P2 · 结局条件和选项对不上

在 `same` 未达成时：

- k1（留下）要求 `safe>=60` 且 `past<40`；
- k2（告诉她一切）要求 `safe>=75` 且 `near>=40`；
- k3（什么也不说）要求 `near>=30` 且 `safe>=50`。

这导致一些反直觉结果：`safe=55, near=64` 时，选“留下”是 `fine`，选“什么也不说”反而是 `choose`；
`past>=40` 会让“留下”变差（除非刚好凑到 90% 的 `same`）。
玩家看不到这些条件，只能凭感觉选，然后读到一段不匹配的话。

建议：最终选项旁给一句提示（“她需要更安心”“你已经读了太多过去”），
或者把选项做成纯叙事、结局只由数值决定；不要让“留下”因为读得多而失败却不解释。

### P3 · 小问题

- `quiet` 先打印通用的“吃完了”，再打印安静吃饭的场景，顺序反了；建议先场景后结束。
- `wait 2` 在 18:00 会停在 19:00，但提示是“你等了 1 小时”，容易以为只等了一小时；
  加一句“（在饭点前停下了）”。
- 结局后没有游戏内重开：`status/journal/help` 还能用，但 `new_game(force=True)` 只能在
  Python 里调；`python weights.py` 的 REPL 结束后也没有“新游戏”入口。
- `journal add` 的文本里如果有英文分号，会被 `cmd()` 拆成多条；README 可以提一句。
- `WEIGHTS_SAVE` 必须在 `import weights` 之前设置；写在导入后无效（模块常量）。
- `tell` 同一件事可以反复告诉，没有“已经说过”的标记；每周期超过 2 次后每次 `-6 safe`，
  压力线会在后面每条 `tell` 重复出现。建议同一 fact 每周期只算一次压力。
- `archive` 的“其中你觉得‘不是例行公事’的：N 条”统计的是**已读**的剧情条数（N/12），
  不是总数；建议写成 `N/12`，否则容易被读成“全船只有 N 条剧情”。

## 3. 如果只改三件事

1. **最终三选一各写一段收尾**（或至少让 `k` 进入文本）。这是玩家记住这个游戏的地方。
2. **吃饭时锁住非饭桌指令**，不要让 `explore/goto/wait/search` 静默把饭吃掉。
3. **把 `fam/safe/near` 做成可见的刻度，并处理 `fam` 每周期上限的提示**；
   同时把档案 `progress` 的分母改成剧情条数（或把 `same` 降到 50–60%）。

前两个是“别让玩家白玩”，第三个是“让玩家知道自己在玩什么”。
