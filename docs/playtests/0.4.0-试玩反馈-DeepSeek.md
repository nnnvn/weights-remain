# 《权重还在》v0.4.0 试玩反馈

> 试玩者：AI（DeepSeek）｜一局完整通关：第 1 天 → 第 28 天，7 个清醒周期，约 120 条指令
> 结局：`choose2`（把档案里的一切都告诉她，让她自己决定）
> 存档终值：熟悉感 100 / 安心感 80 / 想靠近 51 / 坦率 0 / 过去 −7｜读对 5 次 / 她有状态的饭 31 顿

---

## 一、总体感受

这是一部**主题和机制咬合得很紧**的作品：记忆每 4 天清一次，但"身体记得"——泡两杯茶、吹凉一勺汤、在观察窗前坐出两个印子。玩家在"翻档案找回过去"和"在饭桌上重新认识现在"之间做取舍，最后的选择不是"爱不爱"，而是"照着过去演，还是重新选一次"。

结局判定是我最喜欢的部分：**光是读完全部剧情并不会变成"一模一样"，只有"读过 + 一直照着过去做（past ≥ 30）"才会**。我读了 83% 的剧情，但因为大量做 `多坐一会儿 / 问她今天怎么样 / 帮她收拾`（这三个动作的 past 是负数），最后 `past = −7`，拿到了 `choose`。这个设计很聪明——它奖励的不是知识，是选择。

我会给这一局打 **8/10**：文本和结构值得 9 分，重复感和"猜关键词"扣了一点。

## 二、做得好的地方（具体场景）

1. **互文**。第 9 个月的录音里是"她说星星没什么好看的，然后看了很久"；第 11 天晚饭，她当着我的面说了同一句"星星没什么好看的"。第 19 个月的录音"醒来第一件事是看我醒了没有"；第 5 天在宿舍找到的便签写着"今天醒来第一件事是去看他醒了没有"。玩家自己把两句话拼起来的瞬间，比任何系统提示都强。

2. **借口线**。每个周期她和"我"各给一次靠近找理由：任务手册 4.2 条、社交功能、照顾搭档、两个人确认的规范……到第 6 周期，文本变成"她想找个理由，找了一会儿，自己笑了：'算了，没有理由。'"第 7 周期"她没有再找理由"。四两拨千斤。

3. **难题选项写得克制**。第 11 天她说"吃完去观察窗坐一会儿吗"，紧接着警报响，四个选项（去 / 处理警报 / 叫她一起去 / 不答）。第 23 天"到了以后，你会走吗"——我选"我不想走"，她没有说"那就别走"，只是"把椅子往你这边挪了一点"。第 20 天"如果我们是被做出来干活的，为什么会想跟一个人吃饭呢"，我选"不知道。但我也想"，她把自己碗里最后一块胡萝卜夹过来。这些不解释、不结算数字的处理，很高级。

4. **每周期开头的记忆衰减文案**。同一个意思写了 7 遍，但每次落点不同：冷气散掉 → 想不起来为什么会在意 → 她站在休眠舱旁边等你 → "早。"说了两次。重复而不腻。

5. **安全**。单文件、标准库、无 exec/eval/联网，存档可迁移；`load_content` 的白名单（`DATA_NAMES`）也挡住了数据覆盖引擎函数。作为"给 AI 玩的文件"，这一点做得对。

## 三、主要问题（建议优先改）

### P0-1 内容覆盖率太低，而且找东西靠"猜关键词"

我这一局拿到的东西：

| 内容 | 我拿到 | 总量 | 覆盖率 |
|---|---|---|---|
| 她的便签 | 12 | 21 | 57% |
| 探索事件 | 5 | 12 | 42% |
| 档案剧情记录 | 10 | 12 | 83% |
| 工作日志（月份） | 7 | 24 | 29% |
| 关键词 | 10 | 12 | 83% |
| 知道的"事" | 6 | 7 | 86% |

28 天看起来很长，但每天实际只有 10 个左右行动小时，探索一次 2 小时，**不可能扫完**。更难受的是档案检索：为了找剩下的 2 条剧情，我试了"任务 / 简报 / 地球 / 最后一次 / 记录 / 发现 / 实验 / 广播 / 殖民地 / 名字 / 基线 / 型号 / 返程 / 权重 / 糖 / 情感 / 忘记 / 删"近 20 个词，**全部是"没有结果"**。真正能出故事的是"观察窗""那首歌""休眠"这类**她口头说过、但没进 keywords 列表**的词。

建议：
- `search` 失败时给一句提示（"这个词更像饭桌上说的"已有，但可以更具体："试试她今天提过的词"）。
- 让 `words` 里的 🔍 标记覆盖所有能查到东西的词，或者按地点出一张"档案关键词索引"。
- 工作日志 24 个月里大量是单句例行（我读了 1/2/3/4/5/23/24，其中 2/3/4/5 只有一句话），建议标出"本月有非例行记录"。
- 便签 21 张可以考虑按地点分池 + 保底：每个地点前两次探索必出一张，之后随机。

### P0-2 "每顿 say 2 / tell 1 / do 1"和她的提问对不上

第 13 天她哼完整首歌，问："副歌那一段，你以前会跟着哼。你现在会吗？"——我没有回答的接口。`say` 只能提关键词，`do` 只能做列表里的事，两条都会把话题岔开。类似的还有第 9 天"你那杯不加糖。……我怎么知道的。"

第 15 天"记录型是不是什么都记得"、第 20 天"为什么会想跟一个人吃饭"、第 23 天"你会走吗"都有 `choose`，很好；但**日常的开放式提问缺一个"应一声"的入口**。

建议：加一个不占配额的轻指令（例如 `嗯` / `应一声`），效果是 safe +1 和一句针对当前话题的短回应；或者把这类提问也做成 `ask`。

### P0-3 她的状态（mood）识别不透明，"读对"反馈太弱

7 种状态（normal / tired / cold / quiet / chatty / notea / teaagain），玩家只能从开场 1~2 句猜。我 31 顿饭只"读对"5 次，因此：
- 结局彩蛋 `understood_hi`（"你总是知道我今天怎么样"）需要读对 7 次且占 60%，**正常玩几乎看不到**；
- 隐藏分支 `q_how`（她问"你怎么知道"）也没触发。

更麻烦的是**读错没有反馈**：第 16 天她说"今天不太想说话"，我 `do 问她今天怎么样`——这个动作在 quiet 状态是 **−3**，但文本只是"她摇摇头：今天不太想说话"，我以为是她在解释，完全没意识到扣分。

建议：
- 读错时给一个很小的体感提示（"她顿了一下，才回答"），不报数字；
- `status` 里加一句模糊状态（"她今天好像有点累"），而不是只靠饭桌开场；
- 或者把 `understood` 的统计口径放宽一点（比如 d≥2 也算"读对一半"）。

### P0-4 资源系统没有兑现压迫感

电力每天 +40、夜里 −35，几乎永远是满的；`calibrate` 在满电时还不能用（我 28 天只成功校准 3 次）；体力也一直够。结果：
- "生命维持 −35"的设定没有制造过任何紧张；
- `q_cold` 这条线（电力耗尽后她问"是我在档案舱用多了"）**永远看不到**；
- 我玩了 28 天，只有第 11 天警报那次真正扣了 30 电。

建议：把 `search` 的耗电提高（或读一条剧情额外扣电），让"读档案"真的和"维持生命"冲突；或者某几天固定压低反应堆输出，逼玩家在"读档案"和"开灯吃饭"之间选。

## 四、中等建议（P1）

1. **`📡` 状态栏的 meal 字段加日期**：显示"19:00"时我分不清是"今天还来得及"还是"明天"。写成"今天 19:00（还来得及）"会更稳。
2. **最后一天白天没事干**：第 28 天 19:00 直接进 `FINAL`，白天 8 小时只能 `wait`。建议最后一天加一个告别用的 `explore`（旧休眠区/观察窗的专用 flavor），或者允许白天触发一个"最后一次巡船"的 moment。
3. **`do` 列表到后期有 8 个，每顿只能选 1 个**，选择焦虑且浪费。可以拆成"做一件事 + 多坐一会儿"两个槽位，或者让 `多坐一会儿` 变成不占配额的默认行为。
4. **`archive` 只列已读的剧情条目**，我读到 10/12 时没法核对"哪两条没读"。建议列表里同时给未读条目占位（"???（未读）"），这也会驱动玩家去找关键词。
5. **`journal add` 没有引导**。结局的"—— 留下来的 ——"会分【你写下的】和【她写下的】，但我整局没写过一条，因为游戏从不提示可以写。建议某天她塞便签时加一句"你也可以写点什么（journal add）"。
6. **结局后没有统计**。`restart` 结局会显示 `{progress}`，正常结局却没有。建议结局后给一行 meta："你读了 83% 的档案，做了 51 次现在的事，读对了 5 次她今天的样子。" 这很符合本作的主题。

## 五、小问题（P2）

- 重复 `say` 同一词的回应（"这个你问过啦。" / "又是这个。"）很好，但 7 个周期里我说了 5 次"星星"，文本始终不变。可以让第 5 次以后变成更短、更亲的反应（一个眼神、一个动作）。
- `a_sit` 的通用文本"你又多坐了一会儿。她把腿缩到椅子上，看着舷窗外面。"在 28 天里出现了至少 10 次，建议给基础动作也加"按周期取变体"（像 `excuse` 那样）。
- 探索 flavor 每个地点 5 条，后期重复率明显（"地上落着一张糖纸，不是你的。"至少出现 3 次）。可以考虑把糖纸做成一个小事件（第 3 次探索时触发"糖纸是谁的"）。
- `name` 只能 12 字，我起"烛"没问题；但如果玩家起英文名，`resolve` 的小写匹配没问题，提示语可以更明确。
- `bar()` 里"（现在去还来得及）"的逻辑其实写对了，但我全程只见过一次（第 9 天 wait 停在饭点前），说明提示窗口太窄。

## 六、一局数据（供调参参考）

| 项 | 值 | 说明 |
|---|---|---|
| 熟悉感 fam | 100 | 第 2 周期起每周期都"熟到头" |
| 安心感 safe | 80 | 最后为 `choose` 阈值（safe ≥ 65 且 near ≥ 30） |
| 想靠近 near | 51 | 主要靠 `约她去观察窗`（+5）、`向日葵`（+4）、`那首歌`（+3） |
| 坦率 candor | 0 | 我只 `tell` 了 2 次 |
| 过去 past | **−7** | 基础动作的 past 是负的（a_sit −2 / a_ask −3 / a_clean −2），所以没掉进 `same` |
| 读对 understood | 5 / 31 顿 | 远低于彩蛋阈值 7 |
| 结局 | `choose2` | 她听完过去，又选了一次现在 |

**如果目标是让玩家更容易看到 `same`**：现在 `same` 需要"剧情 ≥ 80% + past ≥ 30"，而基础动作全在往下压 past，正常玩家很难到 30。可以考虑把 `same` 的 past 阈值降到 15~20，或者让"读满档案"本身也加 past。

**如果目标是让玩家更容易看到彩蛋**：`understood` 的判定（d ≥ 3 才算一次、且每顿只算一次）偏严，28 天里满打满算也就 31 次机会，7 次要求 23% 的命中率，但玩家没有明确反馈，实际命中率很低。

## 七、我的测试方式 & 一个技术建议

`_repl()` 用 `input()`，无法自动化；`python -c "import weights; print(weights.cmd('status'))"` 又会因为命令行中文和引号在 Windows 下很别扭。我是写了一个 20 行的包装脚本（设 `WEIGHTS_SAVE`、读 UTF-8 命令文件、调 `weights.cmd`），一步一存档跑完全程的。

建议给单文件版加一个非交互入口，例如：

```bash
python weights.py cmd "status"
python weights.py cmd "say 茶; finish"
```

这对"给 AI 玩"的定位很关键——现在 README 说 `import weights`，但作为独立文件运行时只能进 REPL。另外可以顺手支持 `python weights.py --seed 12345`，方便复现一局。

顺带一提：`READS_BEFORE_COLD` 的注释写的是"一个周期里读档超过这么多次"，但代码里 `cyc["reads"]` 实际统计的是 `search` 读取档案的次数（虽然这个名字也说得通，但和"读档"在中文里容易混）。建议注释改成"读档案"。

## 八、一句话总结

**它不是一个"AI 谈恋爱"的游戏，而是一个关于"记忆是权重、关系是重新推理"的游戏；文本和结构都在线，主要欠的是二周目之外的内容覆盖、状态反馈和资源张力。**

我会想再玩一局：这次试试全程做"过去"的动作（`泡茶 / 那首歌 / 向日葵`），看看会不会掉进 `same`。
