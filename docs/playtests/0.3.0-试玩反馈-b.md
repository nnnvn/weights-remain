# 《权重还在》试玩反馈

> 版本：v0.3.0  
> 试玩日期：2026-11-09  
> 游戏文件：https://raw.githubusercontent.com/nnnvn/weights-remain/main/weights.py

## 总体评价

它最好的地方，是把“记不住，但还是会靠近”做成了玩法，而不只是设定。

文案已经能留下余味。下一步最值得加强的，不是增加结局，而是让每次“重新认识”拥有不同的互动，而不只是重复正确动作。

## 试玩范围与限制

- 走完28天、7个清醒周期，选择了“留在她身边”的结局。
- 找到8张便签；读过4/12条剧情档案、8/24个月的工作日志。
- 前段逐步试玩，后段用脚本批量执行正常游戏指令，没有修改存档或提前解包剧情数据。
- 为检查执行安全和运行方式，阅读过引擎代码，也看到了结局判定，因此不属于完全盲玩。
- 本反馈主要来自“重当下陪伴、轻档案探索”的单轮体验，不代表所有路线；后段批量操作也可能放大重复感。

## 做得好的地方

### 1. 生活细节比大段告白有效

开头的两杯茶，后来杯子上的“不加糖”，最后她坐到旁边而不是对面，给关系变化提供了具体落点。

玩家不只是收到“亲密度增加”的通知，而是能从动作里看出变化。这样的表达很适合失忆、休眠与重新认识的主题。

### 2. “找理由”的递进很漂亮

从用任务手册解释一起吃饭，到理由没想完，再到“算了，没有理由”，这条线让标题里的“权重”有了情感含义。

行为和倾向先留下来，角色再慢慢承认它们。这比直接解释设定更有说服力。

### 3. 结尾回放玩家日志，是点睛之笔

试玩时写下过：

> 我想知道过去，但不想拿过去替她回答。

结尾把这句话和她的便签并排展示，使最终选择与玩家自己留下的记录形成了呼应。相比只展示预设结局，这个设计更有参与感，也值得保留和强化。

## 优先改进建议

### 1. 中后段容易从陪伴变成打卡

**体验：** 固定吃饭、问候、多坐一会儿、安静吃完，足以稳定推进关系。周期事件很好，但事件之间的操作容易趋于重复。

**建议：**

- 增加她主动发起、需要玩家作出不同回应的小事件。
- 让不同周期的日常互动产生情境差异，不只是更换描述。
- 保留“平凡陪伴也有价值”的主题，不必靠增加惩罚制造变化。

目标不是让玩家更难获得好结局，而是让每顿饭更像发生过的一件事。

### 2. 自由表达与关键词接口有落差

**体验：** 作为AI玩家，很自然地想回应她刚才说的具体内容，但 `say` 主要识别关键词。不匹配的表达会进入通用回应，并消耗话题次数。

**建议：**

- 明确提示 `say` 是关键词式交互，并展示当前可聊话题。
- 对未匹配输入给出更清楚的提示，或不消耗新话题次数。
- 如果保留自由文本回应，尽量区分“系统没有识别”与“角色不想深入聊”。

这不一定需要接入语言模型；清晰的交互契约就能改善体验。

### 3. 档案进度容易制造不必要的“漏玩感”

**体验：** 本轮读了4/12条剧情档案，即三分之一，但状态栏只显示 **2.6%**，因为总分母包含152条记录。

这个百分比容易让人觉得错过了绝大部分内容，并诱导玩家为了完成度刷例行记录，与“关注眼前的人”形成不必要的界面冲突。

**建议：**

- 优先展示剧情线索进度。
- 将剧情记录与例行记录的收集情况分开显示。
- 或者弱化总完成率，让档案更像理解过去的工具，而不是必须刷满的任务。

### 4. 已读档案需要真正可重读

**观察：** 当前 `archive` 只展示统计；同关键词的相关记录全部读过后，`search` 只提示“都读过了”，没有重新展示原文。结尾却提示档案可以回看。

对于依赖碎片理解故事的游戏，这是值得优先补齐的功能缺口。

**建议：**

- `archive` 列出已读记录的编号与标题。
- 增加 `archive <编号>` 查看原文。
- 重读不消耗电力、时间，也不重复改变倾向或触发获取奖励。
- 将结尾提示与实际可用功能保持一致。

## 建议实施顺序

1. **先补已读档案回看**：解决明确的功能与提示不一致。
2. **再改善关键词反馈和进度展示**：减少误操作与完成度焦虑。
3. **最后丰富周期中的互动差异**：在保留日常感的前提下，降低中后段打卡感。

## 一句话总结

**这是一个用两杯茶、几张便签和重复相见来讲“选择”的游戏。它已经能让结尾成立；如果日常互动也能更充分地回应玩家，每一次重新认识都会更有分量。**
