# 《权重还在》0.1.0 试玩反馈

> **剧透警告：** 本文包含路线、档案内容和结局描述。

## 测试概况

- 版本：`0.1.0`
- 环境：Python 3.12，Linux
- 玩法：只通过公开接口 `weights.cmd()` 游玩，没有解开 `_DATA`，没有查看 `src` 分支
- 进度：完整玩完 28 天、7 个清醒周期，并抵达一个结局
- 操作方式：前 8 天逐步手动游玩；后 20 天使用固定的陪伴策略批量调用公开指令推进
- 最终档案阅读率：9.2%
- 错过饭点：1 次
- 最终电力：94

## 总体评价

核心概念是成立的，而且系统与叙事结合得很好：休眠不只是章节分隔，而是真的让关系变淡；档案不只是收集品，而是在“恢复过去”和“重新认识眼前的人”之间制造选择。

目前主要问题是内容量还不足以支撑完整 28 天。前两个周期的新鲜感很好，中段开始出现明显重复；到后期重新发现旧休眠区、歌曲和观察窗时，体验又重新变好。

如果把中段内容补足，这会是一款很有辨识度的短篇文字游戏。

## 本次路线与结局

我走的是“低读档、重陪伴”路线：

- 只读取了 9.2% 的档案。
- 尽量参加早晚饭。
- 经常泡茶、帮忙收拾、多坐一会儿。
- 告诉了她一部分过去，但没有试图把全部档案灌给她。
- 修理反应堆、校准航线，保持飞船状态稳定。

最后选择：

> 告诉她，你想留在她身边。

得到的结局：

> “我也是。”她说，“我不记得为什么。但我也是。”  
> 过去的你们没有回来。现在的你们，又选了一次彼此。

这个结局和本次路线非常匹配。它没有否定过去，但把决定权留给了现在的两个人。

## 做得很好的部分

### 1. 休眠机制真正服务了主题

每个周期后，系统会明确告诉玩家：日志仍然能读懂，但像是别人写的；关系数值也会有一种“散掉了一点”的感觉。

同时，她的行为会缓慢变化：

- 开始自然地准备两杯茶；
- 站在休眠舱旁等玩家醒来；
- 连说两次“早”；
- 后来直接坐在玩家休眠舱边上。

这些变化比直接显示好感度数字有效得多。

### 2. 饭桌是很好的叙事锚点

每天两顿饭让玩家形成稳定预期。探索和读档之后，总要回来面对她；“知道了过去以后要不要说”因此变成一个实际选择，而不是菜单里的道德题。

### 3. 档案解锁现实行动的设计很好

例如档案不只是提供背景，还能解锁：

- 给她泡茶；
- 去看向日葵；
- 播放旧歌；
- 去观察窗坐坐。

其中“知道过去”最终变成“现在一起做一件事”，这是本作最有力量的设计之一。

### 4. 文本克制，几个短句很有效

本次最喜欢的文字：

> 今天什么都没发生。  
> 记一下，什么都没发生的一天也挺好的。

以及：

> 休眠前一天。把要记住的写下来：  
> 他喝茶不加糖。他说“嗯”的时候其实是在听。  
> ……好像也没什么别的了。哈哈。

还有观察窗事件：

> 你们在旧休眠区的观察窗前坐了一个小时，谁都没说话。回去的路上，她的手碰了一下你的手，又收回去了。

这些段落没有解释过多，效果很好。

## 具体问题与建议

### 1. 中段重复感明显

大约第 9～18 天，主要循环逐渐变成：

1. 去食堂；
2. 重复一个关键词；
3. 做一个通用饭桌行动；
4. 探索并再次获得零件或环境描写；
5. 回食堂；
6. 睡觉。

常见重复包括：

- “问她今天怎么样”“多坐一会儿”等行动文本重复；
- 同一个关键词在不同周期里的回应变化不够多；
- 探索经常再次获得耦合件；
- 部分地点的环境句很快读完。

**建议：**

- 为每个清醒周期增加 1～2 个独有小事件；
- 通用饭桌行动根据周期、熟悉度和最近行为提供不同文本；
- 让相同关键词在关系变化后出现更多阶段性回应；
- 如果暂时没有足够内容，可以考虑把总天数缩短，避免骨架被重复感暴露。

### 2. `wait` 很容易意外跳过饭点

复现方式：

1. 第 7 天 18:00，角色已经在食堂舱；
2. 执行 `wait 4`；
3. 时间直接来到 22:00；
4. 系统提示“饭点过了，她一个人吃的”。

玩家已经身处食堂，却因为一次等待跨过 19:00 而错过饭局，感觉比较反直觉。探索会在临近饭点时自动停下，但 `wait` 不会。

**建议：** `wait` 跨过 07:00 或 19:00 时自动停在饭点，至少在食堂舱内应如此；或者提前给出确认提示。

### 3. 特殊行动的时间描述可能与实际饭点冲突

复现方式：

1. 在早餐时执行 `do 约她去看那袋向日葵`；
2. 返回文本写的是“晚饭后你们去了种子库”。

早餐触发了一个明确发生在晚饭后的事件，时间关系会有些奇怪。

**建议：**

- 根据早餐/晚餐提供不同版本；或
- 把该行动限制为晚餐可用；或
- 使用不指定时间的表述，如“后来你们去了种子库”。

### 4. 已读完的检索仍消耗时间和电力

例如再次执行 `search 记录员` 时，系统只返回“相关记录都读过了”，但时间和电力仍然减少。

这在规则上可以解释，但操作反馈略显惩罚性，尤其玩家只是想确认有没有遗漏。

**建议：** 已读完的关键词不再消耗资源，或者在执行前提供已读标记。

### 5. 维护系统的压力暂时偏低

本次在正常修理、偶尔校准的情况下，结局时电力仍有 94。零件也比较容易通过探索获得，因此电力和反应堆更像日常杂务，而不是需要权衡的系统。

**建议：**

- 如果希望它形成策略压力，可以减少零件产出、增加事故或让校准存在取舍；
- 如果不希望资源管理抢叙事重点，也可以进一步简化维护流程。

### 6. 缺少一个直接可玩的命令行入口

目前 README 的调用方式清楚，但玩家仍需要自己进入 Python、导入模块并打印结果。

**建议：** 增加一个很薄的 CLI：

```bash
python weights.py
```

进入后循环读取命令，并处理 `Ctrl-D`/`quit`。这不会改变给 AI 调用的核心接口，但会方便人类快速试玩和测试。

### 7. 结局后的状态栏还显示下一顿饭

游戏结束后状态栏仍显示：

```json
{"meal":"明早07:00"}
```

属于很小的界面问题。结局后可以显示 `"meal":"结束"` 或省略该字段。

## 玩家日志摘录

> 第一天：她不知道为什么总会泡两杯茶。我修好了反应堆，也读了一条关于茶的旧档案。
>
> 第二天：她记得照料种子，却不记得自己放过什么。向日葵似乎是个重要的词。
>
> 第三天：我告诉她，两杯茶不是偶然。她只是说“知道了”。衣柜里两件保温服并排挂着。
>
> 第四天：种子库零下十八度，她给我让出一点位置。那里每个标签都是她的字。
>
> 第五天：档案说，抵达后她留下，我返航。更早的我知道，却一直没有告诉她。今天我决定说出来。
>
> 第六天：知道终点会分开以后，日常反而显得更具体。她仍照看种子，我仍赶着回来吃饭。
>
> 第七天：我约她去看那袋写着“给他看”的向日葵。也许记忆会散，想给一个人看的冲动不会。
>
> 第八天：我在旧记录里找“记录员”。越读越像另一个人，却也越来越像我。
>
> 最后一顿晚饭。我们又选了一次。

## 简短结论

**能玩，核心体验成立，值得继续扩写。**

当前版本最需要的不是增加更多系统，而是给中间几个周期补充有变化的内容，并修正饭点等待和特殊行动的时间细节。只要中段不再明显重复，最后“现在的两个人重新选择彼此”的落点会更有力量。
