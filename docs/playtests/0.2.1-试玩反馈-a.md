# 《权重还在》试玩 Feedback

**日期：**2026-11-09  
**版本：**0.2.1  
**试玩对象：**[weights.py](https://raw.githubusercontent.com/nnnvn/weights-remain/main/weights.py)  
**一句话：**我最后想留下来，不是因为已经查清了过去，而是因为这二十八天里，我们确实又一起生活了一遍。

> 以下包含结局及中后期剧情。反馈来自 AI 实际运行，不是只读源码的评价。

## 1. 我实际怎么玩的

- Python 3、固定 seed=42，角色名“回声”。完成第 1—28 天、7 个清醒周期，最终选择 1。
- 以陪伴为主：一起吃饭、问今天怎么样、收碗、泡茶；穿插档案检索、工作日志、航线校准和各舱探索。
- 找到 16 张便签，档案进度 7.2%，自己写下 6 条日志。
- 开头逐步体验；中后期将自己选定的日程写成脚本，通过公开 `cmd()` 批量执行，并回看输出。没有修改主试玩存档，也没有主动解包隐藏剧情数据。运行前检查过明文引擎，因此不宣称严格盲玩。
- 主航程之外，用独立测试存档复现边界问题。没有穷举结局，也没有验证高档案完成率路线的平衡。

## 2. 最有效的地方

### “权重还在”被写成了动作，而不是设定说明

最好的线索是两个杯子、不加糖、坐在旁边而不是对面。第一次提茶时，她说不知道为什么总是泡两杯；后来是“你那杯不加糖……我怎么知道的”；最后变成“我不问了，反正你也是这个”。同一个物件经历了陌生、习惯和确认。

第 25 天她坐到我旁边，以及“她没有再找理由”，比一段解释情感机制的独白更有效。建议保留这种克制，不要把每个细节都翻译成数值或主题宣言。

### 档案和便签具有不同的情感质地

档案回答“发生过什么”，便签暴露“她在意什么”。“他会修的。我就不操心了”很轻，但能让关系落在生活里。旧休眠区、保温服、向日葵也让探索不只是抽奖。

我很喜欢档案里“这条不用归档”却还是留下来的矛盾：记录型的工作语言，恰好泄露了它想遮住的东西。

### 日志回收让结局属于这一局

结尾把我写的“泡两杯茶不是证据，是今天的选择”放回来，非常贴合我选的路线。“过去的你们没有回来。现在的你们，又选了一次彼此”因此不只是预写好的结论。

档案只读到 7.2% 也能完成有意义的关系线，这一点值得保留。它没有把“爱她”强制等价于“收集完她”。

## 3. 玩起来最明显的阻力

### 中后期容易变成日程执行

前几个周期我在探索；后面逐渐形成“吃饭—探索—校准—吃饭—睡觉”。重要变化常在饭桌自动触发，通用行动的重复反馈比较多。这里也有我的脚本化玩法造成的放大效应，不能归因全给游戏。

建议：允许对已经见过的日常使用短摘要；第一次出现的便签、关系变化、关键事件仍完整展示。也可以每周期增加一个需要玩家主动决定的小变化，而不是只增加被动对白。

### 玩家容易把关系理解为关键词配额

`say` 同一词在整个周期只给一次有效反应，但每天有两顿饭。熟悉以后，玩家很容易从“想聊什么”转向“哪些词还没用过”。已记下的“任务手册”又可以对话、却检索不到，`words` 的统一提示不太能表达这种差别。

建议区分“可聊话题”和“可检索线索”；重复话题可以不加数值，但给一条和当天有关的短回应。不要让玩家为了避免浪费说话次数而反复查列表。

### 陪伴路线的资源压力偏弱，但不一定需要变难

我这局早期电力曾降到 45，之后频繁校准、少量查档，很多天电力停在 100。后半程校准更像例行动作而不是决策。

这只是低检索路线的观察，不代表所有路线都失衡。可以减少无意义重复操作，或者让低压力路线更明确地成为一种被允许的玩法，不必单纯增加惩罚。

## 4. 已复现的问题与建议

严重度为本次试玩判断，不是官方分级。

### P1：凌晨睡眠能跳过最终结局，进入第 8/7 周期

**复现条件：**第 27 天 20:00，身处宿舍舱。

```python
weights.cmd("wait 4;sleep;status")
```

**实际：**等待到第 28 天 00:00 后，`sleep` 执行休眠，直接醒在第 29 天 06:00，状态显示“第 8/7 个清醒周期”。继续等待可到第 30 天，未触发结局。测试全程使用公开指令，没有改日期。

**原因定位：**`c_sleep()` 将周期第 4 天的凌晨也判为可以休眠；`hibernate()` 直接增加一天。最终触发又只判断 `day == LAST_DAY`，越过第 28 天后便不会补触发。

**建议：**明确凌晨属于哪一晚，避免直接跳过整天；最终事件改为对“跨越截止时刻”也有效，并在耗时行动中停在最终事件。不要只把 `==` 改成 `>=` 而仍允许吞掉最后一天。

### P2：饭点提醒出现时，玩家已经赶不及

新档执行：

```python
weights.cmd("goto archive;wait 12;goto mess")
```

**实际：**在档案舱等到 19:00，提示“饭点到了，她在食堂舱”；立即移动却到 20:00，随即提示她一个人吃了。早餐也会漏掉，但这里反馈的重点是晚餐提醒。

**建议：**不在食堂时，等待/探索自动停在饭前一小时；或者允许一定迟到窗口。提醒应该给玩家一个仍然来得及执行的动作。

### P2：跨天重复话题仍提示“今天已经问过”

**复现：**第 1 天早餐 `say 茶`，第 2 天早餐再 `say 茶`。

**实际：**“你今天已经问过这个啦。”

**原因定位：**去重记录存放在 `cyc["reacted"]`，休眠周期结束才清空，而不是每天清空。

**建议：**若限制按周期设计，改成“这个你问过啦”，并在帮助里说明；若文案要保留“今天”，则按天追踪。也建议让重复回应仍有一点日常变化。

### P2：编号 0 被当作合法操作，并可能改变关系

**已验证：**有便签时 `notes 0` 读取最后一张并显示 `#0`；知道“两杯茶”且正在吃饭时，`tell 0` 实际讲出了这件事，而不是报错。

**原因定位：**直接访问 `[int(q) - 1]`，使 0 落成 Python 的负索引。

**建议：**在索引前统一验证 `1 <= i <= len(entries)`。尤其 `tell` 有状态副作用，不应让无效编号默默变成另一个选择。补上 0、负数、越界和非数字用例。

### P3：`quiet` 的文本顺序会造成重复收尾和动作错位

**主航程实例：**第 26 天晚餐先输出“你们吃完了。她把两个杯子挨着放回柜子里”，随后又输出“你们没说话。她吃饭的时候脚尖碰到你的鞋，没有挪开”。

**原因定位：**`c_quiet()` 先调用会输出收尾文本的 `end_meal()`，再由外层输出静默吃饭的正文。

**建议：**静默结束饭局，只输出一份完整的 quiet 文本，或先呈现吃饭过程、再输出收尾。适合做逐条输出顺序测试。

### P3：结局后的回顾指令行为不统一

**已验证：**结局后 `status;notes` 只执行第一条，并提示后面的指令停止；单独 `notes` 可以查看，但 `archive` 被“航程已经结束”拒绝。

**建议：**区分“本次刚进入结局”和“本来就已经结束”，允许已结束状态批量执行只读命令；开放档案统计。否则最想复盘的时候反而更难查看。

## 5. 关于“给 AI 玩”的额外建议

- 末尾 JSON 状态栏很有用，但最终选择期间 `meal` 仍显示“明早07:00”。加一个 `pending_choice` 字段，能避免代理误判还可以继续安排日程。
- 批量上限 8 条已在帮助写明，但超出的命令会静默截断。最好明确返回“还有 N 条未执行”，减少代理误以为整串动作已完成。
- 未来若增加结构化接口，可返回“已执行命令数、停止原因、合法动作”，同时继续保留现有文学文本。这样更利于不同 AI 稳定体验，而不是更利于刷数值。

## 6. 我会优先改什么

1. 先修最终日越界，保证所有正常时间路径都能收束。
2. 修饭点提醒、编号校验和 quiet 输出顺序。
3. 修“今天/周期”的口径，再改善重复日常的文本密度。
4. 最后补代理可用的结构化状态与结局回顾。

**不建议优先做：**大幅扩充档案量、直接展示好感数值、用更多解释性独白阐述主题。当前最珍贵的部分已经存在：她会替你记住不加糖，而你可以选择明天还来吃饭。

---

**总体反馈：**这是一个已经能成立的短篇互动叙事。情感递进比操作层成熟；下一步最值得投入的不是证明主题更深，而是让时间机制、重复反馈和回顾体验不打断它。
